## 1. User

Using the kids learning app skill from https://github.com/AOSSIE-Org/FlagQuiz, build an educational game based on the classical Memo game, using the same style, look and feel and icons as the Flag Quiz game in https://github.com/AOSSIE-Org/FlagQuiz . Reuse FlagQuiz's components as much as possible.

Here are some additional requirements:

* For the user profile creation, instead of letting the user design a custom flag, let the user choose a 2D geometrical shape and a color.

* For the game selection, let the user choose between various sets of cards and the following game parameters:
- How many pairs of cards to display on the screen. The possible numbers to choose should be those that can be easily displayed in the screen as a grid. Perhaps, show this option not as a number, but as grid icons to choose from. Or think about alternative ways of doing this parameter value selection in an intuitive way.
- the maximum number of seconds that a pair on cards remains shown after pbeing picked. The default should be 5 seconds.
- In the multiplayer case, the maximum number of rounds a player can play successively while guessing correctly, before the next player plays. The default should be 3.

* The goal is to have several sets of cards, each set tagged by topics. When selecting the game, it should be possible to filter by topic. So, a set of cards has 3 properties: its name, a list of tags/topics, and a list of cards.

* In the game selection screen, each card set should show a random sample of its cards. I think 4, 6 or 9 sample cards per set could look well. But consider alternatives.

* Each card is an image and a description.

* The app is multilingual. Therefore, the names, descriptions and tag/topics must be present in all supported languages.

* For now, create the following sets of cards:
- "2D Geometric Colored Shapes". The shapes should be: circle, equilateral triangle, isosceles triangle, scalene triangle, right triangle, square, rectangle, rhombus, paralelogram, trapezium, pentagon, hexagon, heptagon, octagon, nonagon, decagon, star, crescent, cross, heart, ellipse, ring, semicircle, dodecagon, pentadecagon, icosagon, circle sector, lemniscate, trefoil, quatrefoil. The colors should be the rainbow colors (red, orange, yellow, green, blue, indigo, violet) plus black, grey, white, brown, pink. Generate images for all combinations of shapes and colors. The description of the cards should be their colors and shape names. For example, the description of a red circle should be "Red Circle". The first character of each word in a description should be capitalized.
- "Capitals of the World". Each card should show 4 photos of a capital and the description of the capital should be of the form "Paris (France)". Use the capitals and photos already available in the FlagQuiz repository. Combine each capital's 4 photos in a single image. The frame of this image should be black and there should be a thin black line separating the 4 photos in the image.

* We will add more sets later.

* When selecting a set of cards, the user should also have the option of importing or creating a new set of cards.

* Importing asks the user to upload a zip file containing the images and a json file with the data (name, tags, descriptions) of the set and its cards or to provide the URL of such a zip file.

* Creating a new set of cards redirects the user to a card set editor, where the user can input the name of the set and its tags as well upload or drag and drop images and provide descriptions for these images. The image upload or drag and drop should allow the user to upload or drag and drop several images at once, so that it is not tedious.

* The card set editor should allow users to export the card set as a zip file that contains a json file and all the images.

* The card set editor should also allow users to upload the card set to their own Google Drive account. Follow recommended practices for authenticating to Google Drive from a purely local frontend-only web/pwa app.

* So, the game selector will contain two types of card sets: built-in card sets and custom card sets created by the user. Custom card sets should have a small edit button in the top right corner of the cards showing them. clicking on the edit button takes the user to the card set editor. As in FlagQuiz's user selector, there should be a discreet delete button that allows custom card sets to be deleted.

* The card set editor should impose string length limit for the names, tags and descriptions, to ensure that these strings are displayed correctly, without overlaps and oveflows.

* When the users are creating/editing a card set and input names, tags and descriptions, it should be assumed that the language they are using for the inputs is the currently selected language. Because the game is multilingual, we will need to translate this description to multiple languages. Think about different options of how we can achieve this. Implement your recommended option, but inform me of all the options you have considered.

* When custom card sets are created or imported, they should be given a unique local id, to ensure that custom card sets with the same name do not clash.

* Flag Quiz has 4 types of user score: golden star, silver star, golden checkmark and green checkmark. In the memo game, these scores, should be computed as follows:
   - green checkmark: how many times the user has matched two cards correctly, across all games/cardsets.
   - gold checkmark: how many times the user has matched two cards correctly in the currently played cardset. Replace this icon by an icon that shows two cards.
   - silver star: use this as a counter of rounds in the game. Replace the star icon by a more suitable icon for a round counter.
   - gold star: use this as a counter of how many times the user has played games with this card set up to completion.

* In the statistics modal, show:
   - The streak, as in Flag Quiz.
   - A table where rows are card sets and columns are: the user's matched cards score and the user's gold star score for games with that card set.
   - The rows should be sorted by decreasing matched cards score.

* Note that, because there can be unbounded number of card sets, scrolling in the statistics modal is unavoidable. Take this into account in the UI/Layout design.

* When the users are playing a game, the description of a card they picked should be shown below the card when the card is turned and should be spoken aloud via text-to-speech.

* When a user picks two unmatching cards, the cards should remain shown until the maximum number of seconds or until the user clicks, whatever comes first.

* When users pick a card, there should be an animation turning the card around. When unmatching cards are turned back, the same animation should be used.

* When users pick a matching pair of cards, there should be an animation gradually reducing the size of the cards and moving them towards the user's name and profile icon in the top right corner, until they disappear from the screen.

* After all these changes, commit.

## 1. Assistant

Built Memo from Flag Quiz's code and skill and committed it as the first commit of the repository. See the README for features, the translation options considered (on-device Translator API + manual edits + original-language fallback + translations carried in zip files, implemented; cloud services and bundled models rejected), the Google Drive setup (Google Identity Services token model, `drive.file` scope, in-memory token revoked after upload) and the card set zip format. Verified with svelte-check, 283 unit tests, and Playwright in Chrome and WebKit at 1280×720 and 844×390 (a full game, the card set editor with zip export/import, multiplayer turns, Arabic in dark mode, on-device translation with a fake Translator, offline play).
